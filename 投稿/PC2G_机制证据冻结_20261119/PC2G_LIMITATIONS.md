# PC2G 机制证据的适用边界

现有证据最明确地支持 HUSTbearing 固定 20 Hz 有标签、80 Hz 留出任务上的结论。保持 65 Hz 入选位置、批内顺序和每头损失权重后，使用源端真值替换入选错标，三个配对种子的 Accuracy 与 Macro-F1 均提高。以下边界决定这项发现在正文中应怎样表述。[Oracle 预注册](../../output/pc2g_hust_65hz_oracle_preregistration_20261119/oracle_preregistration.md) · [配对结果及审计](../../output/pc2g_hust_65hz_oracle_preregistration_20261119/oracle_final_report.md)

## 1. 三种统计单位对应不同问题

| 单位 | 当前数据 | 对应解释 |
| --- | --- | --- |
| 源训练样本出现次数 | 65 Hz 的 A 在三种子中共 521,989 次入选，292,087 次错标。批内允许同一窗口重复出现。 | 描述训练监督暴露的次数和类别构成。 |
| 目标振动窗及原始记录 | HUSTbearing 的 80 Hz 目标每类一条原始记录，每条产生 81 个完整窗，共九类 729 窗。 | 描述固定留出任务的分类情况。相邻无重叠窗仍来自同次采集，合并种子时同窗重复计数。 |
| 优化种子 | 种子 0、1、2 使用同一训练任务和同一批留出窗。 | 均值、样本标准差和配对方向描述固定任务上的优化波动。记录、工况和轴承总体的重复测量需要独立采集设计。 |

HUSTbearing 的这批数据中，数据发布者已确认同一健康状态在不同频率下使用同一轴承。记录互斥与窗不重叠支持留出工况评价，未见轴承个体是更宽的外推目标。正文采用逐种子配对差和样本标准差，三种子全同向可写为“观察到一致方向”。[划分报告](../../output/pc2g_cross_dataset_stage2/domain_split_report.md) · [文件与物理重复核查](../../output/pc2g_cross_dataset_stage2/leakage_audit.md) · [逐种子差值](../../output/pc2g_hust_65hz_oracle_preregistration_20261119/oracle_paired_comparison.csv)

## 2. 角色诊断、关闭监督和纠错回答不同问题

- **源域角色比较**描述监督质量的角色依赖性。20→35 Hz 有标签角色改变了提供真值的记录、辅助训练任务与另一个无标签源。共享 65 Hz 源的入选错误率由 55.957% 变为 26.181%，可以报告其方向及幅度。单一来源的独立贡献、转速本身及特定采集记录的贡献尚未分离。[角色轮换报告](../../output/pc2g_hust_role_rotation_20261118/PC2G_role_rotation_final_report.md)
- **B−A**描述屏蔽 65 Hz 两个主头整项伪标签 CE 的净影响。正确和错误标签同步退出直接 CE，65 Hz 仍参加一致性、全批前向及辅助路径。B 的故障判正常比例从 68.416% 降至 48.920%，Accuracy 平均变化 −0.549 个百分点，三个种子判对具体故障的总次数从 37 降至 25。[四臂路径干预](../../output/pc2g_hust_65hz_path_20261119/HUST_65Hz_path_intervention_report.md)
- **O−A**描述冻结入选集合后替换错误标签的净影响。这个差同时包含移除错误 CE 目标与加入正确 CE 目标的作用。**O−B**描述在同一入选集合上提供全正确标签相对整组关闭监督的结果。两部分各自的贡献无法从 A、B、O 中分解，M 当前没有纳入已完成证据。[Oracle 比较定义与结果](../../output/pc2g_hust_65hz_oracle_preregistration_20261119/oracle_final_report.md)
- **Oracle 的真值作用**限定在已入选 65 Hz 位置和两个主头的纠错。该机制对照使用额外源端信息，正文实验表在名称和表注中标明。当前预算与协议下观测到的目标结果可量化纠错的净影响，100% 的入选标签正确率并不规定目标性能的数学上界。[源端放行记录](../../output/pc2g_hust_65hz_oracle_preregistration_20261119/all_sources_complete.json)

## 3. 为什么 Oracle 提升后总体表现仍偏低

O 的目标 Accuracy 为 18.884%、Macro-F1 为 12.548%。同一批 80 Hz 窗口在三个种子下共出现 1,944 次真实故障评价，其中 170 次判对具体故障、814 次判为其他故障、960 次判为正常。正常类 Recall 为 100%，八个故障类中仍有五类 Recall 为零，表明剩余错误同时包含检出不足和故障间混淆。[Oracle 逐类指标](../../output/pc2g_hust_65hz_oracle_preregistration_20261119/oracle_class_metrics.csv) · [故障去向总表](../../output/pc2g_hust_65hz_oracle_preregistration_20261119/oracle_final_report.md)

O 相对 A 的中度滚动体 Recall 增益为 +7.407 个百分点，种子 0／1／2 分别为 +6.173／+7.407／+8.642。重度复合的均值为 +47.737 个百分点，三个配对差为 −1.235／+45.679／+98.765。中度内圈的平均 Recall 下降 2.058 个百分点。主结果以 Accuracy、Macro-F1 与全部逐类结果共同支撑，重度复合用于说明类别和种子之间的幅度差异。[逐种子配对及类别结果](../../output/pc2g_hust_65hz_oracle_preregistration_20261119/oracle_paired_comparison.csv)

纠错控制住了 65 Hz 已入选位置的标签内容。未入选位置依然没有直接分类监督，35 Hz 伪监督及跨工况表征和决策过程保持各自的训练约束。20 Hz 的 Raw 和 Full+B 对训练窗已达到 100% 的拟合，现有固定末步协议无独立源验证记录，源验证泛化程度未知。目标混淆可以定位错误流向，无法据此量化未覆盖的样本、跨工况特征变化、分类边界偏移及其交互各占多少。因此，论文把这些因素写作待区分的解释。[HUST 目标错误和源拟合核查](../../output/pc2g_cross_dataset_diagnostic_20261118/HUST_failure_analysis.md)

## 5. 可写入正文的讨论段落

在 HUSTbearing 的固定 80 Hz 留出任务中，65 Hz 入选错标的目标影响可以通过固定集合纠错部分检验。保持入选位置和归一化权重后，使用源端真值替换错标，提高了三个配对种子的 Accuracy 和 Macro-F1，也增加了具体故障的正确识别次数。各故障类别的收益仍有差异，且多个类别召回率为零，表明这一干预只解释了当前跨工况退化的一部分。现有混淆结果无法把剩余误差分配给源端监督覆盖、表征偏移或分类边界偏移。入选集合、工况和采集记录构成当前机制结论的适用条件。

## 6. 后续问题与证据冻结范围

若后续检验三个种子结果的稳定性，可以预先固定比较口径，再扩展到五个配对种子，并为新增种子建立对应 A 轨迹。独立采集重复与多目标工况评价对应更广的外推问题。面向无标签纠错时，还需要单独验证置信度、熵或一致性等可观测量能否识别高风险伪标签。现有源端真值诊断只承担机制测量。以上均为后续研究问题，本次冻结以已有实验档案为准。

# PC2G · HUSTbearing 65 Hz Oracle 伪标签纠错预注册

2026-11-19 · 草案，待确认。当前仅审阅代码和已有源端归档。120 步技术检查、正式训练和新增 80 Hz 评价均等待授权。

## 1. 问题与对照

在固定样本、入选次数和名义损失权重的条件下，仅把 65 Hz 已入选的错误硬伪标签替换为源域真值，检验它对留出 80 Hz 故障识别的影响。固定 20 Hz 有标签，35 Hz 和 65 Hz 为历史训练协议中的无标签源，80 Hz 整域留出。三臂使用相同种子 0、1、2 和第 5000 步检查点。

| 实验臂 | 65 Hz 两个主分类头的伪标签交叉熵 | 65 Hz 一致性直接项 | 处理 |
| --- | --- | --- | --- |
| A | 原 Full+B 的入选样本及校正后硬伪标签 | 开启 | 复用三个历史模型及结果 |
| B | 对完整 65 Hz 伪标签 CE 项置零，保留原前向与采样 | 开启 | 复用三个历史模型及结果 |
| O | 复用 A 的入选样本、顺序和权重，只纠正其中的错标 | 开启 | 新训练三个 Oracle 模型 |

历史三种子均值中，A 与 B 的 Accuracy 分别为 12.803% 和 12.254%，Macro-F1 分别为 5.495% 和 4.707%。B 的故障判正常比例从 A 的 68.416% 降到 48.920%，而三个种子合计判对具体故障的次数从 37 降到 25。整体表现与故障预测去向需要同时检查。[已有四臂实验报告](../pc2g_hust_65hz_path_20261119/HUST_65Hz_path_intervention_report.md)

预注册检验两个预期。第一，O 相对 A 能改善第 5000 步的 Accuracy 与 Macro-F1。第二，若 O 减少故障判正常，还要观察判对具体故障的次数是否增加，以及中度滚动体和重度复合两类 Recall 怎样变化。两项预期都保留零收益、反向及混合结果。

| 配对差 | 回答的问题 |
| --- | --- |
| **O−A，主对比** | 固定入选集合和权重后，替换 65 Hz 错标对目标域结果的净影响。 |
| O−B，次对比 | 相对于屏蔽整条 65 Hz 分类监督路径，恢复同一入选集合上的全正确监督有什么影响。 |
| B−A，历史次对比 | 同时移除原有正确标签和错误标签的 CE 后，目标域结果怎样变化。 |

O−A 包含移除错误目标和加入正确目标的共同作用。O−B 同时恢复原本正确和后来纠正的标签。用这三臂可以区分“在原集合内纠错”和“关掉整组监督”的净效果，但无法分别估计只移除错误 CE 和在原错误样本上加入正确 CE 的独立效应。本轮只做 A、B、O。Oracle 将入选标签正确率设为 100%，属于额外使用源端真值的机制参照。目标域性能仍由实验检验。

## 2. 固定干预

1. 每个种子使用其对应的历史 A。以 A 的逐步 `indices`、65 Hz `actual_mask` 和已入选位置的 `actual_labels` 为准。A 是 Full+B，因此这里的原集合和原标签分别等于 `q_mask`、`q_labels`。每次出现按“步号、物理源域、批内位置、源域局部窗口索引”识别，同一窗口重复出现时分别保留。禁止用去重集合替代。
2. A 的布尔掩码没有记录送入 CE 的顺序。以同种子 Raw/B0 归档的校正 logits 作为排序依据，在历史同版本 PyTorch、CUDA/GPU 和 FP32 调用形状下，逐步、逐分支运行原逐类排序函数。按原预测类递增顺序，从该类全部候选的熵排序中恢复前缀。逐步核对恢复的成员与 A 掩码完全相等，并核对原预测标签。记录入选内部及入选边缘的精确熵平票。冻结有序批位置、窗口索引、A 标签和摘要。锚点 logits 只用于恢复顺序，A 归档是成员和原标签的唯一来源。排序平票若无法按原后端及归档证据恢复，则停止。全 5000 步复核不需要模型前向或优化更新。
3. 用锁定清单中 65 Hz 记录的拼接顺序和窗口索引定位源端真值。逐步仅对 A 已入选位置比较真值。标签相同则保留 A 的标签，不同则替换为对应真值。两个主分类头消耗同一个目标向量。在 O 中，65 Hz 的动态预测和历史队列可照常计算并接受检查，但其输出不决定入选成员、顺序或 CE 标签。65 Hz 真值只提供给 O 的两个主头 CE 和独立审计。普通训练批接口、辅助分类、先验与队列、MMD、熵、一致性和所有非 O 配置继续走原接口。
4. 两个主头各自以当步 65 Hz 原入选数为 CE 均值分母，保留原系数 1 和分步 `ramp(t) = 2 / (1 + exp(-10 * t / 5000)) - 1`。空入选沿用原实现的可微零值。35 Hz 走原筛选和 CE，并逐步核对样本、标签及顺序。20 Hz 的主头真实监督及两个辅助分类头的真实监督继续沿用原实现。一致性覆盖每步 3×64 个源窗口，以 192 为分母，权重为原来的 0.1×ramp，包含 65 Hz 的全部采样位置。这里的固定指样本、计算约定和权重。纠错后的主网络参数、实际损失数值和梯度可以变化。
5. 使用 A 的预处理、网络、初始化、批次及统计扰动随机流、BatchNorm 缓冲区恢复规则、原始所有损失与 Adam 优化配置。每源每步 64 个窗口，逐类筛选比例 0.6、先验历史窗口 128 批、MMD 权重 0.5、熵权重 0.005、Adam 初始学习率 0.001、inverse 调度及权重衰减 0.0005。技术检查同样用 5000 步的调度分母。代码改动仅允许在专用 Oracle 回放与审计入口，普通 PC2G 八配置保持原实现。

## 3. 技术检查与放行条件

本次静态审查已核对三个种子全 5000 步的源采样、掩码和标签。A 的 65 Hz 入选发生 521,989 次，其中原正确 229,902 次，原错标 292,087 次。这些是归档中的窗口出现次数。三个种子分别有 1,634、1,615、1,657 步出现同一窗口在入选边界两侧的重复采样，其校正 logits 逐位相同。这项证据表明必须保留批内位置。历史 CUDA 顺序还需实际复核。[归档审查及校验摘要](oracle_implementation_audit.json)

阶段一为零优化更新的归档检查。校验冻结清单、源记录及映射顺序、A/B/排序锚点摘要和代码版本。对三个种子的完整 5000 步核对入选成员、原标签、有序窗口位置及两个 CE 的计划样本数。训练进程使用从锁定清单生成的源域视图，保持记录拼接顺序。普通批接口只接收 20 Hz 真值。65 Hz 标签通过 Oracle 专用表交付，源端查表限定为已入选索引。检查时验证 35 Hz 真值、80 Hz 信号及标签均未进入训练进程。

阶段二为 120 次优化更新的技术短检。每个种子从各自相同的初始状态独立运行原生 A 12 步、归档回放 A 12 步、Oracle O 16 步。归档回放 A 保留原标签，用来检验冻结入选序列本身的影响。三个技术运行的权重均弃用。

- 原生 A 与历史前缀核对采样、掩码、原标签和有历史记录的损失项。原生 A 与回放 A 在同环境逐步核对两个无标签域的批内索引顺序、两个主头的 CE 输入和损失、梯度、参数、Adam 状态、BN 缓冲区和随机状态。该比较要求相同值。技术短检验证起始前缀，全程顺序复核依赖冻结档案与原排序调用。
- O 逐步核对所用样本、位置、先后顺序、重复次数、分母、权重和其他监督分支。核对两主头收到同一纠错向量，原正确标签逐项保留，所有原错标逐项改成源端真值。检查未入选位置没有直接 65 Hz 分类 CE 梯度，实际总损失和梯度有限。用同一组 logits 对照替换前后的 CE 和梯度，检查 65 Hz 直接分类干预只落在原错标位置。术语“直接”限定为隔离的 65 Hz CE，未入选窗口仍可参与一致性和其他原定计算。
- 检查 20 Hz 辅助 CE 与 35 Hz 伪监督的输入来源、65 Hz 一致性及 192 分母、原随机流、队列更新及 BN 恢复规则。错误标签纠正可能经共享主网络改变后续预测和损失值，运行核对着重于数据、目标和计算路径。

任一关键检查失败即保留日志并停在正式训练之前。正式运行逐步再次核对归档和实际 CE 输入，三种子均完成第 5000 步且通过源端审计后，才由独立评价流程打开 80 Hz。技术短检和训练期间均不读目标振动信号或目标样本标签。不按 80 Hz 结果重跑、换检查点或调整超参数。

## 5. 固定评价与解释

- **共同主指标**为基于全部 80 Hz 留出窗口的 Accuracy 和九类 Macro-F1。沿用历史指标实现和固定类别表。两项均给出 A、B、O 每种子的结果、三种子均值和样本标准差，以及三组同种子配对差及其均值和样本标准差。统一用百分点表示差值，保留每一条差的符号。
- **机制指标**包括故障被预测为正常的比例（分母为真实故障窗口）、各类 Recall、中度滚动体及重度复合故障 Recall、各预测类别计数和预测正常比例。额外报告真实故障窗口被预测为正确的具体故障、其他故障或正常的计数，以查看预测去向。
- **源端过程指标**包括各步入选计数、原正确保留数、错误纠正数、未入选进入 CE 的计数、按真实类别及原伪标签的纠错计数，以及两个主头分别的 CE 样本数、分母、系数和原始/有效 CE。明确区分重复出现数和唯一窗口数，固定源端指标用于审计与机制解释。
- 若 O−A 两项主指标的配对均值均为正，描述为“两项主指标平均改善”。要求两项指标在三个种子上的配对差均为正，才描述为“三种子方向一致”。O−B 同样独立判读。若仅部分指标或种子改善，按实际方向报告。历史 A 两个主指标的均值均高于 B，同一指标的三种子均值不可能同时满足 O>A 且 O<B。
- 若故障判正常比例下降，且具体故障判对次数未上升，按预测去向变化解释。若仅部分故障 Recall 改善且有类别下降，报告类别间变化及全局指标。若 O 对 A 的整体改善不成立，结论限于“固定入选集合下的纠错单独未显示稳定的总体改善”。只报告三组配对的描述性结果，无显著性、等效性或跨工况普遍性的判定。
